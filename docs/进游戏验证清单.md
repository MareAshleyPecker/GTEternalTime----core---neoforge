## 5. 扳手设 I/O 面的正确手势（**不是 bug**，别再当问题查）

查证结论（GTM 8.0.0 源码）：

| 操作 | 结果 |
|---|---|
| **不潜行**，手持 GT 扳手右键机器**侧面** | ✅ **把该面设成输出面**，覆盖贴图随即出现 |
| **潜行**右键侧面 | 只是**旋转机器**（`MetaMachine.onWrenchClick` 的 `setFrontFacing` 分支），这次交互被旋转吃掉 |
| 不潜行点**正面**（且机器允许 extended facing） | 转 upFacing |

- 原因：`MetaMachine.onToolClick` 里**机器自身先说话**（`:451-452` 调自己的 `onWrenchClick`），只有它返回 `PASS`（= 不潜行 + 非正面）才轮到 trait 的 `AutoOutputTrait.onToolClick`（`:461-464` → `AutoOutputTrait.java:331/344`）。所以 1.20.1 那种"一次右键顺手设定"在 8.0.0 变成了"**潜行=旋转 / 不潜行=设 I/O**"的手势区分。
- 扳手**默认模式是 `BOTH`**（`ToolModeSwitchBehavior.java:54` 的 `getOrDefault(..., ModeType.BOTH)`，而 `:59` 的 BOTH 分支允许 configure items/fluids）⇒ 一次右键会**同时**把物品面和流体面设成该面。
- 只想设其中一种：**潜行右键空气**切模式（`:96-99`，ITEM → FLUID → BOTH 循环，动作栏会提示）。
- 覆盖贴图的条件（只要方向真被设上就一定出来）：`MachineModel.java:277-301` 的 `renderType == null || solid`、`supportsAutoOutput*()`、`itemFace != null && side == itemFace`。

## 10. 多方块测试机（线程仓的第一台消费机器）

> 3×3×3 钢机壳、只吃研磨配方。**这是线程仓唯一能在游戏里被验的地方**，所以 §8 里那几条
> 「需要先有机器」的项都在这里实测。

- [ ] 创造页 MULTIBLOCK 页里能看到「多方块测试机」，名字是中文；tooltip 四行（并行提示、配方类型行、本机两行）
- [ ] 摆出 3×3×3 钢机壳（中间层中心空腔、控制器嵌在第三个 slice 的中行中列）→ 成型；机壳 < 15 格不成型
- [ ] **至少要 1 个能源仓**才成型（`autoAbilities(*recipeTypes)` 给的下限）—— 放输入/输出总线也要成型
- [ ] 维护仓最多 1、并行仓最多 1、**线程仓最多 1**：放第 2 个线程仓 → 结构报错
- [ ] 只认研磨：输入总线放矿石能跑，放别的机器的料不跑
- [ ] **不装线程仓**：成型后只跑一条配方（GTM 原版口径）；机器面板**整块不出现**线程行；Jade 里我们的 provider 连 NBT 都不写
- [ ] **装 1 个线程仓**（如 `thread_hatch_zpm` = 4 线程）：Jade 出现 `线程 4（在用 k）` + 逐配方组绿色进度条；面板文本列出现 `线程 4（在用 k）` / `同时处理 N 次配方运行` / `整机耗电 … EU/t` 与每组两行
- [ ] ⚠️ 同时**会**看到 GTM 那条红字单配方进度条与并行/批处理倍率行 —— 那两个抑制它的 mixin 本切片没移植，属已知显示重复，不是 bug
- [ ] **不同配方各自跑**：总线里放两种可研磨物 → 4 线程时两组同时跑、各自扣料出料，Jade/面板出现两组行且槽位号不同
- [ ] **同一种配方吃多条线程**：只放一种矿石且量足 → 某组 `n 条线程` > 1；`同时处理 N 次配方运行` = Σ 各线程 `totalRuns`
- [ ] **线程仓 + 并行仓**：总处理次数 ≈ 线程数 × 并行倍数；只放刚好 1 次的料 → 产出只有 1 次份（证明并行没被套两遍）
- [ ] **只装并行仓不装线程仓**：线程上限仍是 1，总处理次数 = 那一条线程的并行倍数
- [ ] 结构被打散 / 拆掉线程仓 → 线程全消失且进度不退还；重新成型后从空线程表开始
- [ ] 存档往返：运行中退出重进 → 线程按「配方 id + 进度」恢复；配方被数据包改过的那条消失
